# 笔录审查测试与体验优化设计

## 目标

以 7 份内容丰富、格式接近正式询问笔录的虚构材料覆盖电信网络诈骗常见场景，逐份跑通模型审查、人工分流、补问、报告、归档和重启恢复，并依据繁忙民警的实际操作路径优化界面。

## 材料范围

保留现有 3 份材料，并新增 4 份：

1. 冒充公检法：老年被害人、电话和视频通话、ATM 转账、所谓“安全账户”、部分通话记录灭失。
2. 投资情感诱导：社交平台、群聊、虚假导师、银行卡和数字货币、多收款主体、前后陈述矛盾。
3. 冒充客服退款：屏幕共享、远程控制、验证码、网贷及多设备操作，电子痕迹部分保留。
4. 线下取现和寄递黄金：网约车或快递交付、第三方协助、多人关系，并故意整块漏问部分规则。

每份材料必须：

- 使用虚构姓名、号码、账户、地址和组织，并在页眉、封面提示及签名区明确标注“虚构测试材料，禁止用于真实案件”。
- 包含案件编号、询问次数、起止时间、地点、询问人、记录人、权利义务告知、身份表、问答正文、核对及签名区。
- 身份表显式包含姓名、性别、年龄、民族、身份证号码、工作单位、现住址和联系方式。
- 同时交付 DOCX 和 PDF；PDF 用于验证真实分页、证据定位和扫描型输入。
- 覆盖七条“三现四流”规则的通过、提问遗漏、回答不完整和不适用边界。

## 民警工作流结论

常规复核不要求输入文字。每个提问遗漏或回答不完整项继续使用“确认问题、加入补问清单、忽略”三选一，选择后自动展开下一待处理项。

手动输入只出现在补问清单，而且是可选行为：系统建议问法可以直接复制，民警需要结合案情调整时再点“编辑”。编辑内容保存到该项人工决定中，报告展示最终补问文本。补问清单提供单条复制和全部复制。

完成复核保持一键操作并自动归档，不增加归档原因。打印入口在归档后显示，避免打印未完成报告。报告补充被害人信息，但未在原文出现的字段统一显示“未提取”，不得推断或生成默认值。

## 数据与接口

继续复用 `ReviewResult.manualDecision.reason` 保存补问清单中的人工改写文本：空字符串表示使用模型建议问法。现有决定接口足以保存该值，不新增数据库表或迁移。

`ReportData` 增加 `victimProfile`，报告数据直接读取任务中已持久化的显式提取结果。个人信息提取允许清理 DOCX 表格产生的分隔符，但不根据出生日期推算年龄，也不把职业描述自动当作工作单位。

## 验收

- 7 份 DOCX 和对应 PDF 均生成成功，逐页渲染无裁切、重叠、乱码或破表。
- 7 份材料均通过当前 Qwen 路径完成审查，并完成所有待处理项的三选一分流。
- 每份均验证补问清单、报告、归档、审查记录回看；至少一次后端重启后仍可读取 SQLite 记录。
- 单条复制、全部复制、可选编辑、自动跳转下一项和报告被害人信息有自动化测试。
- 后端、前端测试、生产构建、Python 编译及桌面和移动端浏览器流程通过，控制台无错误。
