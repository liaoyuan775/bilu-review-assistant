# 七份 DOCX 演示案例接入设计

## 目标

用 `output/doc` 中现有的七份正式排版脱敏 DOCX 替换旧的三段内置短文本案例。保留一个无需等待模型的快速演示入口，其余六个案例走当前真实文档解析、Qwen 审查、证据校验和持久化链路。

## 案例来源

案例目录固定为仓库根目录下的 `output/doc`，只允许以下七个 DOCX：

1. `01-基本完整-电诈询问笔录.docx`
2. `02-明确漏问-电诈询问笔录.docx`
3. `03-复杂场景-APP返利询问笔录.docx`
4. `04-冒充公检法-老年人ATM询问笔录.docx`
5. `05-投资交友-数字货币询问笔录.docx`
6. `06-冒充客服-远程控制询问笔录.docx`
7. `07-线下取现-寄递黄金询问笔录.docx`

演示接口不得按用户输入拼接任意文件路径。后端维护固定案例清单，案例 ID 只映射到上述白名单文件。旧 ID `sample-covered`、`sample-missing`、`sample-telecom` 和对应内置段落不再使用。

## 双通道行为

### 01 快速演示

`01-基本完整-电诈询问笔录.docx` 是唯一快速演示案例：

- 后端真实读取并解析该 DOCX，保证页面展示的原文、页段位置和被害人信息来自实际文件；
- 不调用 Qwen 审查接口；
- 使用与当前 `rules.json` 七条规则和 30 个 `requiredFacts` 对齐的固定 mock 审查结果；
- mock 证据位置必须指向解析后的真实页段，证据文字由后端从该位置读取，不能写死另一份文本；
- 结果来源明确显示“模拟结果，仅用于功能演示”；
- 历史记录和报告继续保留该来源，不得显示为 Qwen 模型结果；
- 支持完整体验结果筛选、证据联动、人工分流、补问清单、完成复核、归档和报告。

快速演示的固定结果目标是“基本完整但仍有少量可复核项”，不能伪造成七条全部通过。具体规则状态和缺失事实由实现前对 DOCX 解析结果与当前 `rules.json` 对照后固化，并以测试断言锁定。

### 02 至 07 真实演示

其余六份 DOCX：

- 后端读取白名单中的真实文件字节；
- 复用 `process_upload` 的完整链路：DOCX 解析、图片识别（文件含图片时）、被害人信息提取、Qwen 分组审查、确定性证据校验、SQLite 保存；
- 新任务固定使用 `mode=qwen`；
- 模型不可用、文件缺失、解析失败或证据校验未通过时，按现有真实任务错误路径处理；
- 不回退到关键词分析或快速 mock 结果。

## 数据模型与兼容

- `ReviewMode.LOCAL/local` 只为读取 SQLite 中已有的 8 条历史演示记录保留，不允许新建 `local` 任务。
- 快速演示不复用 `local` 语义。新增 `ReviewMode.MOCK/mock`，使历史、报告和页面能可靠区分 mock 与 Qwen。
- 普通上传和 02 至 07 的演示任务使用 `qwen`。
- `ReviewTask.mode` 和 `ReportData.mode` 继续作为结果来源的持久化依据。
- 前端审查模式显示：`mock` 为“快速模拟演示”，`qwen` 为“Qwen 模型”，旧 `local` 历史为“旧版本地演示”。

## 案例目录与接口

`GET /api/v1/demos` 返回七条固定摘要，每条至少包含：

- `id`
- `name`
- `pageCount`
- `intent`
- `executionMode`: `mock` 或 `qwen`

`POST /api/v1/reviews/demos/{demo_id}` 不再接受客户端选择模式：

- `01` 由后端固定创建 `mock` 任务；
- `02` 至 `07` 由后端固定创建 `qwen` 任务；
- 未知 ID 返回 `demo_not_found`；
- 白名单文件缺失返回 `demo_file_missing`，不使用旧内置文本兜底。

## 前端展示

新建审查页继续保留“脱敏演示案例”区域，但改为七条：

- `01` 显示“快速演示”标识和“模拟结果”说明；
- `02` 至 `07` 显示“Qwen 完整审查”；
- 模型离线时，`01` 仍可点击，`02` 至 `07` 禁用并显示模型不可用状态；
- 页面文案不得再写“无需模型连接，直接查看七条规则”，而应说明只有快速案例不调用模型；
- 点击真实案例后使用现有轮询和状态展示，不新增假进度。

## 旧代码处理

- 删除 `backend/app/data.py` 中旧的 `_demo`、三份短文本 `DEMOS` 和旧 `DEMO_INTENTS`。
- 删除 `backend/app/services/analyzer.py` 的产品运行时调用。若文件没有其他消费者，则删除该文件。
- `process_demo` 重写为读取固定 DOCX；mock 和 Qwen 只在审查阶段分流，文档解析共用真实解析器。
- 测试中需要的标准 `ParsedDocument` 夹具不得再依赖旧三段文本；使用七份 DOCX 的解析结果或测试专用最小夹具。
- `verify_qwen.py` 使用 02 至 07 中一份真实 DOCX，先解析再调用模型；不能使用 01 mock 或旧内置文本。
- README、PRD、技术手册和 OpenAPI 快照同步更新当前七案例和双通道语义。

## 错误与安全边界

- 案例目录和文件名由代码白名单固定，不开放路径参数。
- 只读取 DOCX；同目录 PDF 继续作为视觉/分页验证资产，不进入当前演示 API。
- 文件读取和解析问题不触发 mock 回退。
- 02 至 07 的 Qwen 问题不触发本地关键词回退。
- mock 来源必须在结果、历史和报告中可辨识，不能只在案例按钮上提示。
- 七份材料均为虚构脱敏材料；不增加真实案件数据。

## 测试与验收

### 自动化测试

- 案例列表固定返回七条，顺序为 01 至 07；旧 ID 不存在。
- 七个白名单文件均存在、可读取并能通过 `parse_document` 形成非空文档。
- 01 创建 `mock` 任务且测试证明没有调用 `review_with_qwen`。
- 01 固定返回七条规则，规则 ID、`missingFacts` 和证据位置均符合当前 `rules.json` 和解析文档。
- 01 可走完人工分流、补问、归档和报告，报告模式明确为 mock。
- 02 至 07 创建 `qwen` 任务，并复用上传处理链路；普通测试 mock 模型响应，不访问外网。
- 02 至 07 模型错误时不回退 mock 或关键词结果。
- 未知 ID、文件缺失和模型离线分别有稳定错误断言。
- SQLite 中旧 `local` 记录仍可读取。

### 浏览器验收

- 新建审查页显示七个案例且移动端/桌面端无溢出。
- 01 明确显示快速 mock 标识，进入结果页后仍能辨认来源。
- 02 至 07 显示真实 Qwen 链路状态并能进入结果页。
- 模型离线时只有 01 可用。
- 旧三案例名称和“电诈条件规则”不再出现在页面。

## 不在本次范围

- 不把 PDF 作为演示任务输入。
- 不建立通用案例上传或案例管理后台。
- 不修改七份 DOCX 的正文和排版。
- 不调整 `rules.json` 的业务口径。
- 不删除 SQLite 中已有的旧 `local` 历史记录。
