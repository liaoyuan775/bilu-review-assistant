# 审查结果问题优先展示与演示处置设计

## 背景与目标

当前审查结果仍按业务组展示，导致较早业务组中的“已通过”可能出现在较后业务组的问题之前；风险提示也主要依赖文字标签，不够醒目。审查 PDF 和补问 DOCX 会直接展示 `money.net_loss`、`transfer_001.transaction_id` 等英文事实路径。演示时还需要逐条选择正式处置方式并重新生成产物，难以快速展示完整归档流程。

本次实现同时完成：

1. 审查结果先展示问题，再展示规则不适用和已通过；
2. 用风险颜色和处置状态清楚标识仍需处理的项目；
3. 仅将“报告 PDF”和“补问 DOCX”中的用户可见字段名称中文化；
4. 为内置演示样例提供单条“测试通过”和“一键测试通过”两种演示捷径。

## 范围边界

- 顶部“原件、报告 PDF、补问 DOCX”等按钮名称不变。
- 原件始终保持上传时的内容，不生成修改版。
- 结构化 JSON 和归档清单的字段结构及内容不变。
- API、数据库中的规则状态、人工状态和事实路径保持英文技术值，不改变兼容契约。
- 正式上传任务不显示任何“测试通过”入口。
- 演示捷径不能绕过抽取失败业务域；失败域仍必须重试成功。

## PDF 与 DOCX 中文化

后端报告展示层新增事实字段中文标签和动态重复实体字段转换，例如：

- `money.net_loss` → “净损失”；
- `transfer_001.transaction_id` → “第1笔转账交易流水号”；
- `withdrawals.count` → “取款记录数量”。

报告 PDF 和补问 DOCX 使用同一组转换函数：

- 审查说明中的英文事实路径替换为中文；
- “缺失或不清字段”使用中文字段名称；
- 规则名称、证据原文、建议补问和人工处置继续使用现有中文内容；
- 规则编号、任务编号、模型名称和文件扩展名属于审计或产品标识，继续保留原值。

结构化 JSON 不参与本次中文化。

## 问题优先排序

结果按四个展示区依次排列：

1. **待处理问题**：自动状态为未询问、回答不清、事实矛盾或待人工判断，且人工处置尚未闭环；
2. **已闭环问题**：上述问题已有 `resolved`、`not_applicable` 或带依据的 `ignored` 终态；
3. **规则不适用**：自动状态为 `not_applicable`；
4. **已通过**：自动状态为 `covered`，始终放在最后。

每个展示区内部继续按现有业务组组织，不丢失业务域上下文。待处理问题在业务组内按高风险、中风险、低风险排序；同风险等级再按未询问、事实矛盾、回答不清、待人工判断排序。

PDF 和补问 DOCX 使用同一问题优先排序，保证页面和下载产物的阅读顺序一致。

## 风险与处理状态视觉

待处理项目同时显示风险等级和人工状态：

- 高风险：红色左边框、浅红背景和“高风险”标签；
- 中风险：橙色左边框、浅橙背景和“中风险”标签；
- 低风险：黄色左边框、浅黄背景和“低风险”标签；
- `pending`、历史 `confirmed`：显示“待处理”；
- `supplemented`：显示蓝色“补问中”；
- 已闭环问题：显示绿色“已闭环”；
- 规则不适用：灰色；
- 已通过：绿色。

颜色只作为辅助，所有状态均保留明确中文文字，避免仅依靠颜色传达信息。

## 演示任务识别

`ReviewTask` 新增可选 `demoId`。通过内置演示样例接口创建的任务记录对应样例 ID；普通文件上传任务保持 `demoId = null`。该字段同时传给前端，用于决定是否显示演示操作。

历史任务缺少该字段时按普通任务处理，不显示演示操作。

## 单条“测试通过”

仅当任务具有 `demoId`、尚未归档且当前项目属于未闭环问题时显示“测试通过”。点击后复用现有人工处置接口，保存：

- 人工状态：`resolved`；
- 处理依据：“脱敏演示：测试通过”；
- 操作人：`demo-operator`。

该操作只闭环当前项目，并使旧归档产物失效。所有问题处理完成后，仍可手动生成归档产物。

## “一键测试通过”

仅在具有 `demoId` 的未归档任务顶部显示。点击后：

1. 后端再次确认任务确为内置演示任务；
2. 若存在抽取失败业务域则拒绝操作并提示先重试；
3. 将所有尚未闭环的异常项目批量保存为 `resolved`，依据统一为“脱敏演示：一键测试通过”；
4. 自动确认该演示文档的解析告警，并记录审计事件；
5. 重新生成报告 PDF、补问 DOCX、结构化 JSON 和归档清单；
6. 返回最新任务。若不存在其他门禁，归档按钮立即可点击，但不自动执行归档。

一键操作不会修改原件，也不会把自动规则状态伪装成“已通过”；顶部未询问、回答不清和事实矛盾数量保持自动审查结果，人工状态显示为已闭环。

## 归档说明

规则不适用和已通过无需人工处理。归档仍要求：

- 所有异常项目已闭环；
- 没有抽取失败业务域；
- 所有解析告警已确认；
- 当前版本的全部归档产物已经生成并通过哈希校验。

## 错误处理

- 普通上传任务调用批量演示接口返回 `demo_action_not_allowed`；
- 已归档任务返回现有只读错误；
- 未完成任务不能执行演示处置；
- 存在失败域时返回 `demo_has_failed_domains`；
- 产物生成失败时保留已写入的人工处置记录，前端提示重新点击“生成归档产物”。

## 测试与验收

1. 后端标签测试覆盖普通事实路径、重复实体字段和未知字段回退。
2. PDF、DOCX 测试确认不再直接出现代表性英文事实路径，并确认问题排在已通过之前。
3. 前端状态测试覆盖四区排序和高、中、低风险顺序。
4. 前端文案与组件测试确认正式任务无演示按钮、演示任务同时具有单条和一键操作。
5. API 生命周期测试覆盖演示任务批量闭环、自动确认告警、自动生成产物，以及普通任务拒绝调用。
6. 浏览器验收使用“五类结果演示笔录”，检查问题排序、风险颜色、单条测试通过、一键测试通过和归档按钮启用。
