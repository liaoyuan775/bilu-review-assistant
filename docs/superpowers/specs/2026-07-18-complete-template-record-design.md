# 完整脱敏询问笔录设计

## 目标

以 `backend/询问笔录模版(1).docx` 为唯一版式和问题来源，制作一份可直接上传到 Bilu 的完整脱敏询问笔录。案例设定为虚构的冒充电商客服退款诈骗，全文事实前后一致，不覆盖原模板。

最终文档写入 `output/doc/完整脱敏-冒充客服退款诈骗询问笔录.docx`。

## 案情设定

- 被询问人、民警、单位、地址、手机号、银行卡、平台账号和订单信息全部使用明显虚构的测试数据。
- 被害人在家中接到冒充电商客服的电话，对方以商品质量问题和退款理赔为由，引导其切换到聊天软件并下载远程协助 APP。
- 被害人自行操作两笔线上银行转账，合计金额与逐笔金额严格相等。
- 案件不包含现金取款、黄金购买、物流寄递或面对面交付；对应问题仍完整回答并明确勾选不适用或无。
- 风险提示、挂失、录音、实名登记、个人信息泄露、证据留存和报案经过均给出与主线一致的答案。

## 模板填写规则

1. 保留模板标题、告知事项、33 个问题的顺序、长题说明、签名区和主要格式。
2. 所有 33 个问答块均有答案；不适用的问题明确回答“无”或“不适用”，不以空白代替。
3. 单选题保留全部选项，恰当选项标记为 `☑`，其他选项标记为 `☐`。
4. 多选题根据案情勾选一个或多个合理选项，不能机械地只勾第一个；每个勾选结果必须与叙述事实一致。
5. 选中某渠道后，填写其对应的号码、账号、昵称、链接、时间、频次或截图留存情况；未选渠道不虚构附属信息。
6. 长题按子项逐项填写，尤其包括首次接触方式、联系方式切换、两笔转账、返利、风险提示和线下交付分支。
7. 金额、次数、时间线和账号归属在全文保持一致：两笔转账之和等于被骗总额，联系方式切换时间晚于首次接触时间，挂失和报案时间晚于最后一笔转账。
8. 文档不得包含真实个人信息、可访问诈骗链接、真实公网 IP 或真实金融账号。

## 生成方式

复制模板 DOCX，在副本中填写页首基本信息、每个答案槽及长题选项。优先保留原有段落和字符格式；需要表达勾选状态时，将模板中的选项改写为 `☑ 选项` 或 `☐ 选项`。不修改业务解析器。

## 验证

- 使用项目 `parse_document` 重新解析生成的 DOCX。
- 断言解析结果为 33 个 `questionAnswers`，且 `answerClarity` 不含 `blank`。
- 检查所有包含备选项的长题均出现 `☑`，并保留未选项 `☐`；多选场景至少存在一处合理的多个勾选。
- 核对两笔转账金额之和、总金额、时间顺序及线上/线下分支一致性。
- 渲染并逐页检查标题、段落、分页、复选框字符和签名区，避免文字截断或版式错乱。

## 非目标

- 不使用真实案件或真实身份信息。
- 不改动原模板、解析器、规则目录、前端或数据库结构。
- 不把这一份样例的解析成功解释为模型业务准确率证明。
