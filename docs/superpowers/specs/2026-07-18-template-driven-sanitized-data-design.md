# 模板驱动脱敏测试数据与中文审查展示设计

## 背景与目标

Bilu 面向民警对电信网络诈骗询问笔录做查漏补缺。当前有效依据是项目内的《询问笔录模版(1).docx》和甲方提供的“三现四流”工作方式。模板决定询问顺序、字段和条件分支；三现四流只用于把模板审查项归并到现场、现物、现痕、人员流、信息流、资金流、行为流等查漏视角，不额外生成模板之外的硬性问题。

本次交付解决两个直接问题：

1. 所有演示和测试 DOCX 从真实模板复制正文结构，再填入虚构脱敏答案；运行时不读取 `output` 目录的旧文档。
2. API 内部继续使用英文标识符，但审查结果页面不直接显示英文分组码、事实路径、实体类型或规则编号。

## 方案

### 模板复制

新增 `template_fixture` 服务，读取模板 DOCX 的 `word/document.xml`，按正文中出现的 `答：`/`答:` 标记顺序替换答案文本，保留问题、模板说明、段落顺序和样式。其他 OpenXML 部件原样复制；损坏的非关键媒体部件可跳过，现有容错解析器继续保留正文并产生可见告警。

模板答案槽位数量必须与解析出的 33 个问答块一致。槽位不匹配直接报错，避免生成看似完整但错位的测试文档。

### 演示目录

演示文档放在 `backend/demo_documents/`，由模板生成器产生。`backend/app/demo_cases.py` 只从该目录读取，不能回退到 `output`。旧生成器保留场景数据，但改为使用同一模板复制器生成 DOCX。

### 中文展示

前端新增中文映射：业务组、事实路径、事实域、实体类型和规则范围均通过映射显示。规则 ID 只作为程序选择键，不在结果卡片中直接展示。搜索仍同时检索内部 ID 和中文内容，保证调试与用户查找都可用。

## 非目标

- 不把三现四流扩展为新的强制规则集合。
- 不修改现有规则状态机、Qwen Schema 或人工处置 API。
- 不读取、迁移或清理 `output` 中的旧文件。
- 不把一次本地模拟流程当成业务准确率证明；准确率后续只在模板对齐的脱敏样例上评估。

## 验收

- 模板生成测试证明输出包含 33 个问答块，问题文本与模板一致，答案来自脱敏数据。
- 七个演示样例均从 `backend/demo_documents` 加载，`output` 路径不再出现在运行时代码中。
- 前端规则结果中不出现裸露的英文组码、事实路径、实体类型或规则编号。
- 运行一次后端相关测试和前端测试，并进行一次本地模拟演示流程验证。
