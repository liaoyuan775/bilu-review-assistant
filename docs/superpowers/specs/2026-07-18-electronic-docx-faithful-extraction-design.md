# 电子 DOCX 忠实提取设计

## 目标

电子版询问笔录上传后，解析层忠实恢复个人信息区和问答原文，并将电子复选框原位转换为模型可理解的状态文字。解析层不建立固定的 33 题业务目录，不判断单选或多选是否合法，也不删除未选项；七域模型负责理解问答语义，确定性规则继续负责审查结果。

真实回归样本使用 `backend/基于原模板填写-冒充客服退款诈骗询问笔录.docx`。

## 当前分包边界

- `app/core`：公共 Pydantic 契约。本次扩充 `VictimProfile`。
- `app/parsing`：DOCX/PDF 忠实读取、问答重建。本次在 `openxml.py` 处理电子复选框。
- `app/review`：个人信息提取、七域模型抽取和审查编排。本次修改 `victim.py` 与 `extraction.py`。
- `app/llm`：模型通信，不拥有文档解释规则。
- `app/data`：版本化审查规则，不建立问答选项目录。
- `app/storage`、`app/reporting`、`app/api`：分别持久化、交付和暴露上述契约。

旧的 `app/services/*.py`、`app/models.py` 等扁平模块已由用户迁移到上述包，本次只在新包内实现，不恢复旧模块。

## 文档解析

### 有序转写

`parsing/openxml.py` 按 OOXML 节点原始顺序读取段落内容。普通文字保持原文；复选框在其出现位置转换为以下文字：

- 明确选中：`[选中]`
- 明确未选：`[未选]`
- 存在方框但状态无法判定：`[状态不明]`

状态标记与后续选项文本保持相邻，例如：

```text
[选中] 电话  [未选] 短信  [选中] APP
```

问答重建继续只依据 `问：/答：` 边界，因此模板题数增减、选项增减不需要更新程序目录。状态文字与选项详细内容作为普通答案原文进入对应 `QuestionAnswerBlock.answer`。

### 兼容的电子方框

同一有序读取函数兼容：

1. 文本字符 `☑/☒/☐/□`；
2. `w:sym` 字体符号，例如当前空模板的 `Wingdings 2 / 00A3`；
3. `w14:checkbox` 内容控件；
4. 旧式 Word 表单复选框。

无法识别的方框不得猜成选中或未选，必须输出 `[状态不明]` 并产生文档 warning。装饰图片继续按现有图片策略处理，不能仅因图片靠近选项就推断选择状态。

### 不做的清洗

- 不删除 `[未选]` 选项；它表示“明确否定”，不同于“文档未提及”。
- 不把答案拆成 phone/app/transfer 等程序实体。
- 不判断某题是单选还是多选。
- 不根据固定题号绑定选项。
- 不用 VLM 猜电子方框状态。

## 个人信息提取

个人信息提取只读取首道 `问：` 之前的文档文本，避免询问人/记录人工作单位和后续案件叙述抢占被询问人字段。若页眉先于正文进入标准化文本，也必须排除页眉/页脚，只使用正文开头的个人信息区。

`VictimProfile` 包含：

| 字段 | 来源 |
|---|---|
| `name` | 被询问人/姓名/“我叫” |
| `gender` | 性别 |
| `age` | 年龄 |
| `birthDate` | 出生日期 |
| `ethnicity` | 民族 |
| `idNumber` | 身份证号码 |
| `contact` | 联系方式/电话 |
| `occupation` | 职业或基本情况回答中的明确职业 |
| `education` | 文化程度/学历 |
| `employer` | 被询问人个人信息区中的工作单位 |
| `address` | 现住址 |
| `registeredAddress` | 户籍所在地/户籍地址 |
| `isNpcRepresentative` | 是否人大代表；明确是/否，否则 `null` |

字段仍允许为 `null`，不通过出生日期推算年龄，不通过职业推断工作单位，不在多值冲突时静默选择后文值。

## 七域模型输入

`review/extraction.py::build_domain_prompt` 继续发送带锚点的全部问答和必要的非问答结构文本，同时加入统一解释：

- `[选中]` 表示文档明确选择，可作为事实候选；
- `[未选]` 表示文档明确未选择，不得作为肯定案件事实；
- `[状态不明]` 表示解析无法确认，模型只能返回不清楚/未知，不得自行判断；
- 选择数量不代表程序已判断单选或多选，模型按问题原文理解。

个人信息单独写入 `ReviewTask.victimProfile`，七域仍按当前规则目录提取 `victim.*` 事实用于确定性覆盖检查；两份结果职责不同：前者服务 UI/报告展示，后者服务带锚点的规则判断。不得用正则结果替代模型证据事实。

## API 与展示

新增个人信息字段同步到：

- 后端 `VictimProfile` Pydantic 模型；
- 前端 `VictimProfile` TypeScript 接口；
- `VictimProfileCard` 字段标签与布局；
- OpenAPI 快照；
- 结构化报告通过现有 `model_dump` 自动包含新增字段。

问答契约不增加 options 字典，仍使用当前 `question/answer/guidance/anchorIds/answerClarity`，复选框状态体现在 `answer` 原文中。

## 错误与兼容

- 未发现复选框时按普通 DOCX 解析，不产生警告。
- 遇到未知电子方框编码时保留 `[状态不明]`，并产生可确认 warning，不能使整份文档失败。
- 旧任务 JSON 缺少新增个人字段时由 Pydantic 默认 `null`，保持可读。
- PDF 路径本次不增加方框检测；扫描件仍属于后续 VLM/图像版面识别范围。
- 当前分包迁移已有与本功能无关的测试失败，实施验证必须分别报告“本功能聚焦测试”和“迁移基线遗留失败”，不能把遗留失败算成本功能回归。

## 验收

1. 指定 DOCX 解析为 33 个问答，答案顺序不变。
2. 电子方框在问答答案中显示为 `[选中]/[未选]/[状态不明]`，状态标记紧邻对应选项文字。
3. 空模板中的 `Wingdings 2` 方框不会静默消失。
4. 指定 DOCX 的个人信息正确提取，特别是 `employer=某测试科技有限公司`，不能提取成询问人工作单位。
5. 出生日期、职业、文化程度、户籍所在地、是否人大代表均进入 `VictimProfile`。
6. 七域 prompt 明确包含三种状态的解释，并禁止把 `[未选]` 当作肯定事实。
7. 前端类型、个人信息卡和 OpenAPI 与后端契约一致。
8. 聚焦解析、个人信息、prompt、API/前端测试通过；基线中不相关的迁移失败单独列出。

## 非目标

- 不支持纸质扫描件或手写勾选。
- 不建立固定的 33 题/选项目录。
- 不在解析层做案件事实清洗或单选/多选校验。
- 不改变七域 Schema、34 条规则含义或审查状态机。
