# Complete Template Record Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate one complete, fictional, sanitized inquiry-record DOCX from the tracked 33-question template and prove that Bilu parses every answer and checkbox branch correctly.

**Architecture:** A one-off Python generator reads the tracked template questions, writes a clean A4 inquiry record with matching question order, and fills each answer from one internally consistent customer-service-refund fraud scenario. A verification script reuses `parse_document` and checks Q&A count, clarity, checkbox coverage, amounts, and chronology.

**Tech Stack:** Python 3, python-docx, existing Bilu parser, Microsoft Word/Poppler rendering.

## Global Constraints

- Do not overwrite `backend/询问笔录模版(1).docx`.
- Write the final file to `output/doc/完整脱敏-冒充客服退款诈骗询问笔录.docx`.
- Use fictional test identities, accounts, addresses, URLs, and phone numbers only.
- Fill all 33 answers; use `☑` for selected and `☐` for unselected options.
- Preserve all relevant choices and allow multiple selected options where the facts require them.
- Keep two online transfers, their total, chronology, and non-applicable offline branches consistent.
