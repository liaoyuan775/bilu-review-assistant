# 审查结果人工处置快速上手

## 1. 先理解页面上的两种状态

页面顶部的“未询问、回答不清、事实矛盾、待人工判断、规则不适用、已通过”是系统根据原文和规则计算的**自动审查状态**。

打开一条结果后显示的“待人工处置、已加入补问、已闭环、人工确认不适用”等是**人工处置状态**。

人工点击”不适用”或”不处理”不会把顶部数字改成”已通过”。只有保存新的补问答案并完成相关业务域重审后，自动审查状态才可能改变，顶部数字才会随新结果更新。

## 2. 推荐操作顺序

1. 点击顶部类别，筛选对应结果。
2. 打开一条结果，核对左侧原文、判断说明、缺失字段和证据原文。
3. 优先使用蓝色主按钮完成补问或核实。
4. 如果不需要补问，再根据事实选择“接受现有材料”“确认不适用”或“不处理并说明”。
5. 处理完全部异常项，重新生成归档产物。
6. 页面显示“归档条件已满足”后执行归档。

## 3. 五类结果分别怎么处理

### 未询问

含义：原文没有找到规则要求的明确问答。

可用操作：

- **补问并重审**：推荐操作。点击后该项进入补问清单并打开补问面板；填写实际补问和回答，点击“保存并重审”后才算闭环。
- **确认不适用**：本案客观上不涉及该规则时使用，必须填写处理依据。
- **不处理并说明**：明确决定不再处理时使用，必须填写原因。

“未询问”没有“接受现有回答”，因为原文中不存在可接受的明确回答。

### 回答不清

含义：原文问到了相关事项，但时间、金额、账号、次数、地点等关键信息缺失或含糊。

可用操作：

- **补问并重审**：推荐操作。补齐缺失内容后保存答案，系统重新审查相关业务域。
- **接受现有回答**：人工核对后认为现有信息足以办理时使用，必须说明接受理由。
- **确认不适用**：确认本案不适用该规则时使用，必须填写依据。
- **不处理并说明**：决定保留问题但不再补问时使用，必须填写原因。

### 事实矛盾

含义：现有材料中的金额、笔数、时间先后或其他事实不能相互对应。

可用操作：

- **核实并重审**：推荐操作。向被询问人或依据材料核实准确事实，再保存实际问题和回答。
- **确认以现有材料为准**：已经人工核对并确定采用哪项材料时使用，依据中应写明采用内容和理由。
- **确认不适用**：冲突所对应规则不适用于本案时使用，必须填写依据。
- **不处理并说明**：决定不再核实时使用，必须填写原因。

### 待人工判断

含义：系统无法可靠判断规则是否适用，需要人工先判断案件场景。

可用操作：

- **确认适用并补问**：确认规则适用且信息不足时使用，保存补问答案后重审。
- **确认不适用**：确认本案不涉及该场景时使用，必须填写判断依据。
- **不处理并说明**：暂不作适用性结论且决定不继续处理时使用，必须填写原因。

### 已通过

含义：规则要求的事实已经明确，确定性校验通过。

该类结果只用于查看证据，不显示人工处置按钮，也不会阻止归档。

系统自动判定为“规则不适用”的结果同样只用于查看，表示已有明确事实证明当前规则的触发条件没有发生，不要求重复人工处置。

## 4. 每个按钮点击后发生什么

| 操作 | 人工状态 | 是否进入补问清单 | 是否立即闭环 | 对顶部自动分类的影响 |
|---|---|---:|---:|---|
| 补问并重审 / 核实并重审 / 确认适用并补问 | 已加入补问，等待记录答案 | 是 | 否 | 暂不改变 |
| 保存实际补问和回答 | 已闭环 | 否，已从待补问状态转为解决 | 是 | 重审后可能改变 |
| 接受现有回答 | 已闭环 | 否 | 是 | 不改变 |
| 确认以现有材料为准 | 已闭环 | 否 | 是 | 不改变 |
| 确认不适用 | 人工确认不适用 | 否 | 是 | 不改变 |
| 不处理并说明 | 已说明不处理 | 否 | 是 | 不改变 |

旧任务中如果看到“旧版：仅确认，仍需闭环”，说明以前只点击了“确认问题”。该状态不能归档，需要重新选择一种闭环操作。

## 5. 补问操作示例

例如“回答不清”提示缺少两笔转账流水号：

1. 点击“补问并重审”。
2. 在“实际补问”中确认或编辑问题，例如：“请分别说明两笔转账的交易流水号。”
3. 在“被询问人回答”中录入实际回答。
4. 点击“保存并重审”。

系统会把这组问答追加到当前解析文档的新版本，只重审受影响的业务域。该规则被标记为“已闭环”；同一业务域内其他旧人工决定如果受新事实影响，可能被重置并要求重新核对。

## 6. 什么情况可以归档

必须同时满足以下条件：

- 自动审查任务已经完成；
- 没有抽取失败的业务域；
- 所有文档解析告警均已人工确认；
- 所有“未询问、回答不清、事实矛盾、待人工判断”项目均已闭环；
- 已针对当前文档和处置结果生成报告 PDF、补问 DOCX、结构 JSON 和归档清单。

以下状态都不算闭环，会显示“未闭环问题”：

- 待人工处置；
- 已加入补问但尚未填写答案；
- 旧版“仅确认”；
- 不处理但没有填写依据。

## 7. 为什么操作后要重新生成归档产物

人工处置、补问重审或确认解析告警后，审查内容已经变化。系统会让旧的报告 PDF、补问 DOCX、结构 JSON 和归档清单失效，以防止归档旧版本。

处理完成后点击“生成归档产物”，系统会重新生成：

- **报告 PDF**：审查结论、证据、建议补问和人工操作记录；
- **补问 DOCX**：用于补充询问和记录处置的工作清单；
- **结构 JSON**：解析文档、事实提取、规则结果、人工事件和版本信息；
- **归档清单**：原件和生成产物的文件名、大小、版本与 SHA-256 哈希。

“原件”是最初上传的 DOCX 或 PDF，不等于报告 PDF。

## 8. 归档后的结果

点击“归档”时，系统会再次校验未闭环问题、解析告警、失败业务域、文档版本和各产物哈希。校验通过后：

- 任务记录归档时间和审计事件；
- 当前审查任务变为只读；
- 不能继续修改处置、记录补问或重新生成产物；
- 原始上传文件内容不会被修改。

当前归档是本系统本地 SQLite 和文件存储中的状态冻结，不代表已经推送到外部正式档案系统。
