# 模板笔录审查性能报告

## 结论

生产初次审查的七业务域模型请求默认并发从 2 提升到 7。并发 7 在固定模型、固定脱敏语料和相同质量门禁下通过 5 轮测试：

- P50：`135.361s -> 71.426s`，改善 `47.23%`。
- P95：`146.894s -> 71.819s`，改善 `51.11%`。
- 质量指纹完全一致。
- 两组均为 35 次请求，零重试、零超时、零 Schema/证据错误。
- 改善超过 10% 准入线，因此接受并发 7。

用户指定按 `7 -> 5 -> 3` 选择最高稳定并发。并发 7 已通过全部准入条件，因此没有继续测试 5 和 3，避免无必要的模型调用。

## 测试条件

| 项目 | 固定条件 |
|---|---|
| 日期 | 2026-07-18 |
| 模型 | `Qwen3.6-35B-A3B` |
| 模型接口 | 项目现有 OpenAI 兼容配置，未更换 provider/endpoint |
| 语料 | `gold-12-complete.docx`，七业务域、92 个事实路径 |
| 文档规模 | 7 个逻辑页、105 个段落、12,257 个规范化字符 |
| 重复实体 | 联系切换 2、转账 2、返款 1、取现 1、线下交付 1 |
| 每组轮次 | 5 次首次审查，不使用缓存 |
| 请求策略 | strict JSON Schema，温度 0，共享 `httpx.AsyncClient` |
| 超时 | 每个模型请求 240 秒，连接 5 秒 |
| 质量门槛 | 每轮先校验事实、实体、规则状态和证据，再计入性能统计 |

解析耗时只有 6-10ms，总耗时由模型推理主导。测试不包含浏览器轮询、人工处理、报告生成和归档时间。

## 质量准入

性能样本不是只测时间。每一轮必须同时满足：

1. 92 个事实的 clarity 和金标准等价值匹配。
2. 五类重复实体数量及每个字段匹配。
3. 34 条模板规则状态匹配。
4. 需要证据的规则具有经过生产校验的真实锚点。
5. 五轮金标准语义指纹一致。
6. 候选汇总质量指纹与基线一致。

两组质量指纹均为：

```text
59a4c404dfe6e57f65e4c965e2b3b8757bcc9a006f783e06c2ef38bb7c502d9a
```

指纹会归一化金标准允许的等价表达和等价证据锚点选择，但事实、清晰度、实体数量/字段、规则状态或缺失字段变化都会导致不一致。所有原始锚点在生成指纹前已通过文档白名单和模板说明隔离校验。

## 实现选择

`backend/app/services/template_extraction.py` 的 `DEFAULT_DOMAIN_CONCURRENCY` 为 7。七个初始业务域共享一个 HTTP 客户端，并由 semaphore 同时发起；每个域仍独立执行最多 3 次结构/证据/临时错误尝试。

定向复核仍只请求实际含糊的事实路径，并使用按域过滤的 focus-only Schema。后续补问复审只运行受影响域，因此不会为了凑满并发重复请求无关域。

没有采用以下方式：

- 不缩减 92 个事实路径或实体字段。
- 不降低 strict Schema、证据或重复实体校验。
- 不缓存首次审查结果冒充性能改善。
- 不更换模型、endpoint 或 provider。
- 不并行多份案件文档；本次并发只发生在同一笔录的七个独立事实域内。

## 复现命令

```powershell
# 并发 2 基线
backend\.venv\Scripts\python.exe backend\scripts\benchmark_template_review.py `
  --runs 5 `
  --case-id gold-12-complete `
  --domain-concurrency 2 `
  --output .runtime\benchmark-before.json

# 并发 7 候选与自动比较
backend\.venv\Scripts\python.exe backend\scripts\benchmark_template_review.py `
  --runs 5 `
  --case-id gold-12-complete `
  --domain-concurrency 7 `
  --baseline .runtime\benchmark-before.json `
  --output .runtime\benchmark-after.json
```

报告 JSON 包含每轮总耗时、解析/审查耗时、各业务域耗时、请求数、token、P50/P95、质量指纹和准入结论。`.runtime` 报告不提交仓库。

## 运维边界

该结论适用于本次模型服务和本机网络条件。模型服务扩容、限流或部署拓扑改变后应重新跑 5 轮基线。若并发 7 出现持续的 429、5xx 或 240 秒超时，应先用同一脚本测试并发 5，再测试 3；任何降级也必须重新通过完整质量指纹和 10% 性能门槛。
